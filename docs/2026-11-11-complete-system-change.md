# 2026-11-11 完整物料调度系统开发

## 背景与当前行为

用户将目标更新为完整完成前后端所有模块。现有工程只有探针、基础七表和天地图空态。业务范围以用户提供 PDF 为准，包含用户权限、地点、规格、库存、调度、损毁照片、操作审计及金华地图联动；本轮追加搜索选点，避免手填经纬度。

## 预期行为与验收标准

1. 用户体系：HttpOnly 会话 Cookie、密码安全哈希、CSRF 防护、登录限流/锁定、退出和改密、用户增改禁用及 admin/dispatcher/inspector 权限；无默认账户或默认口令，提供从标准输入读取口令的首位管理员初始化命令。
2. 地点：仓库/工地/堆场增改停用、负责人、地址，地图搜索/点击/拖拽取点，自动回填经纬度；地点地图展示真实库存汇总与列表/详情联动。
3. 物料规格：编码、名称、类别、单重、尺寸、单位、备注管理。
4. 库存：地点+规格查询、初始录入及带原因的盘点调整，乐观锁，操作审计与库存同事务提交。
5. 调度：新建、待发车取消、确认发车、签收（完好/损毁数量守恒）；发车原子扣来源完好量并增目的地在途量，签收原子转库存。防止重复操作与并发超卖。
6. 损毁：照片上传、上报、审核确认/驳回、修复/报废。运输签收损毁自动生成已确认报告，避免复核二次扣减。独立上报审核时才转损毁库存。
7. 审计：只增不改，记录操作者、请求 ID、模块、动作、目标、脱敏前后值，分页筛选查看。
8. 全部列表有加载/错误/空态/重试，响应式布局，API 参数校验、统一错误及权限校验。图片限制类型/体积/数量，私有鉴权读取。
9. 完成格式、lint、类型、全量测试（含真实数据库、并发、权限和端到端）、生产构建及本地联调。

## 明确的业务规则

- 管理员拥有所有操作；调度员管理地点/规格、调度发车、签收及损毁审核；现场员可读地图/地点/规格/库存/调度，签收、上报损毁；用户管理与库存盘点调整、审计查阅仅管理员。
- 待发车不预扣库存，发车时检查可用量。仅待发车可取消；运输中撤回需后续专门逆向调拨，不静默回滚实物流转。
- 一次性签收，完好+损毁必须等于调拨量。运输损毁直接进入目的地 damaged_qty，并生成 confirmed 报告。
- 独立损毁上报 pending 不扣库存，确认时 normal→damaged；修复 damaged→normal，报废从 damaged 扣除并保留报告历史；禁止重复处理。
- 有库存或未完成调度的地点不得停用；被使用的物料规格不得删除，提供编辑而不破坏历史。
- ID 通过 JSON 十进制字符串传输；时间存 timestamptz，界面 Asia/Shanghai；坐标统一 WGS84，地图区域以金华视野为默认而非用矩形伪造行政边界。

## 影响模块 / API

后端新增 internal/auth、catalog、inventory、dispatch、damage、upload、audit、platform/business，HTTP 入口组装鉴权与域服务。新增会话、上传元数据与锁定字段迁移。前端新增登录及受保护布局、各域 API/页面、地点选点器、真实地图详情/调度入口。

所有业务 API 使用 `/api/v1`，成功 `{data,request_id}`；列表 `data={items,total,page,page_size}`。鉴权 401、权限/CSRF 403、校验 400、冲突 409。Cookie 只用于同源，生产 Secure；不记录密码、会话令牌、照片内容或地图 key。

地图能力已查询：搜索 `/v2/search`、地址解析和逆解析 `/geocoder`。现有 key 为浏览器端，服务端试调返回 403 / 301012，需使用浏览器授权路径；若采用 Gin 代理则需专用服务器 key。点击取点由现有 Leaflet 完成，不依赖地名检索是否命中。

## 兼容、风险与回滚

保持健康探针与 envelope 兼容，所有业务路由受认证保护。沿用已有七表，新增迁移不修改已应用的版本 1。先在独立 *_test 库验证，再显式应用本地开发库。上传文件位于被忽略的本地存储目录，生产可替换对象存储；私有图片不作为公开静态文件暴露。无自动建默认管理员，只有操作者明确输入用户名和密码才创建。回滚必须先备份业务库和图片；应用级状态逆转不能替代物理库存调整。
